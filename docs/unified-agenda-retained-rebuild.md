# Replay Unified Agenda from retained originals

The source-only path reconstructs Unified Agenda subjects without reading a prior table or acquiring new bytes. The application preserves its existing strip-only normalization and nested-list ordering. The source reader validates every record's RIN and `PUBLICATION_ID` before an edition contributes rows.

`normalize_retained_edition(body, edition=..., on_source=...)` reads a caller-selected original offline and emits a success receipt after the complete edition scan. `build_unified_agenda(..., source_only=True, editions=..., records=..., source_receipts=...)` requires explicit editions and an offline reader. It refuses a prior merge file, existing output and duplicate or missing native identities. The normal incremental route includes the qualified 2004 editions in backfill.

SpicyDocs owns the historical repair: only the two full original hashes, sizes and byte positions in `spicy_docs.sources.unified_agenda.repair` may substitute the measured `0x19` with `U+2019` in memory. Original downloads stay unchanged. A reduced excerpt, changed malformed original, second control byte or other illegal XML does not receive general sanitization. A well-formed later revision needs no repair. The receipt records original and parsed-copy hashes, byte lengths, RIN, position and the named rule. This is a qualified parsing interpretation, not a claim that the original contained a legal Unicode apostrophe.

The builder writes `unified_agenda_source_inputs.json`. Its output's file metadata pins that manifest and carries compact repair receipts; the published table keeps this metadata (`regulations_shape.mapped_table`) without adding columns, and a scheduled run journals the manifest as `unified-agenda-editions` beside the edition files it retains as source evidence. The shaping writer buffers bounded batches rather than every selected edition's shaped rows.

`UnifiedAgendaRollup(output_dir=...).build_table(work, build_unified_agenda, source_only=True, editions=..., records=..., source_receipts=...)` is the entry point: it runs this path and writes the published table, with no receipts (ss-vse3; `docs/agenda-cfr-receipt-archive.md`). It is also the only way a column added to the reader reaches editions an incremental run would otherwise restore from a prior; the incremental build re-reads, through its bounded backfill, any edition none of whose prior rows was read for `related_rins`; a carried row that re-read no longer lists stays NULL, and the build logs how many.

The 2026-10-10 qualification directory this page used to name (`corpora/spicyregs/metadata/historical-rebuilds/20261010/agenda/`) is no longer retained. The current proof is the 2026-10-30 related-RIN replay recorded on ticket ss-cdaa: all 60 retained originals, verified by SHA-256 and size, through the source-only path (then `regulations_ingest.unified_agenda_generation`, removed with the receipts), then `EXCEPT ALL` both ways against the live subject over every pre-existing column, and the new column against an independent lxml parse. Row counts alone are insufficient; nulls, repeated values and ordered nested fields compare by value. The baseline serves only as a comparison target; the proof does not publish or delete it.

Tests use isolated test-only approvals for reduced fixtures; production approval remains bound to full originals. Run the dated proof with the locally coordinated SpicyDocs source checkout until the dependency owner updates the pinned source-reader wheel. No package or vendor pin changes are made by this adapter work.
